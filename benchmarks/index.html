How we measure

Each report compares Nox and ComfyUI on one GPU, with warm runs, cold runs, peak VRAM, generation settings and SSIM output similarity. Both engines run the same checkpoints, prompts, seeds and output sizes. Benchmarking Nox against ComfyUI explains how we check that both sides do the same work, and shows the outputs side by side.

Known issues

ComfyUI’s Qwen High outputs are black

At the High output size both engines use SageAttention. For Qwen Image 2512 and Qwen Image Edit 2511, SageAttention 1.0.6 in ComfyUI produces NaN values and ComfyUI saves a black image. That is why their High SSIM is close to 0. The ComfyUI times in those two rows come from runs that didn’t produce a usable image, so they are not a fair comparison.

Cold times depend on the storage

A cold run includes reading the checkpoints from disk, so its time depends on where the machine stores them. Cloud GPUs often load from a network volume, and that can make cold runs much longer than on a local SSD. Compare cold times between engines within one report, not between reports. Within one benchmark run, Nox and ComfyUI always load from the same volume.

FLUX.2 Klein 9B Edit reuses weights in Nox’s cold run

Both engines run their cold requests one after another in a single process. FLUX.2 Klein 9B Edit runs right after FLUX.2 Klein 9B, and both pipelines load the same transformer and text encoder. On GPUs with enough memory, Nox still has those weights loaded when the Edit run starts.

ComfyUI loads the weights again, which is why the speedup there is dramatic. We don’t know yet why ComfyUI doesn’t reuse them.
