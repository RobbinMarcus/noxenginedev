Comparing quantized backends

With Comfy Kitchen, ComfyUI got 2.5× to 3.4× faster in our benchmark. Nox still wins every cold run, by 1.40× to 2.89× on average.

Our first benchmark post put Nox 3.2× ahead of ComfyUI on an RTX 4080. After it went up, the ComfyUI team kindly told us to run with --use-ck-attention on CUDA 13+, which enables their new Comfy Kitchen attention backend. ComfyUI’s warm times in our benchmark dropped by 2.5× to 3.4× on average, depending on the GPU.

What we had wrong

The benchmark harness pinned PyTorch 2.9.1 built for CUDA 12.8. On a CUDA 12 build, ComfyUI disables the CUDA backend of Comfy Kitchen, its own kernel library. That backend holds the INT8 ConvRot matmul and attention kernels, which are exactly what the INT8 checkpoints in this benchmark need. Without them ComfyUI falls back to much slower paths. The fix moves the harness to the CUDA 13.0 build and starts ComfyUI with --use-ck-attention.

Ideogram 4 was a real gap in Nox. Its attention heads are 256 wide, which our Sage attention kernel didn’t support, so Ideogram 4 ran on a slower fallback. ComfyUI’s Comfy Kitchen attention has no such gap. Once we added 256-wide heads, Ideogram 4 High went from 16.08s to 8.28s, now 1.07× ahead of ComfyUI. On the H100, Nox already wins Ideogram 4 High by 1.10× with a 256-wide Sage variant. A cuDNN kernel measured faster there, so that case is still open.

Qwen Image Edit 2511 High was a gap in the harness. ComfyUI ran a small warmup before each High case. The old setup needed this warmup because it restarted ComfyUI with Sage attention for High. That warmup already encoded the 1536×1536 reference image, so the measured request skipped work that Nox did inside the timer. Now both engines encode the High reference inside the measured request.

Cold, low and high runs

The first post measured one cold and one warm request per pipeline, at one size. The benchmark now reports three runs:

RunSeedImagesVideosState
Cold421024×1024768×512First request for a model, weights read from disk
Low431024×1024768×512Weights loaded
High431536×15361344×768Weights loaded, right after Low

Low is the warm run from the first post with one change: MiniMax-H3 now renders 124 frames instead of 56, so Low and High differ only in resolution.

Cold now means cold from disk. A fresh process alone isn’t enough, because Linux keeps recently read files in its page cache and the “cold” load would read them from RAM. Both harnesses evict every checkpoint file from the page cache once, when the process starts. Each pipeline’s first request is its cold run, so later pipelines that share a checkpoint find it already loaded. FLUX.2 Klein 9B Edit runs right after FLUX.2 Klein 9B on the same weights, which is why its cold time can be shorter. The pipelines execute in the exact order shown in the table on the front page.

Nox uses SageAttention in every run. ComfyUI uses Comfy Kitchen attention in every run. We’re now comparing the fastest attention backend each engine has.

MiniMax-H3 High is the one case with sparse attention on both sides. Nox keeps 15% of key tiles, as described in our sparse attention post. ComfyUI uses Veda with its trained sparsity. This is the only case that isn’t identical. We kept it because no sparse attention runs in both engines, and ours is close to Veda’s.

Side note about ComfyUI on a cloud host

The RTX 5090 rerun on Runpod hit a problem: ComfyUI’s video runs were up to 9× slower than they should have been. The machine reported 120 CPUs to the container but only allowed it 14.45 cores of CPU time. PyTorch starts a thread for every reported CPU, so ComfyUI kept hitting that limit and was paused in 38% of scheduling periods. On this particular host, limiting ComfyUI to the allowed cores and threads manually brought its times back in line:

ComfyUI, RTX 5090, LTX-2.3 VideoNo limit14 cores
Cold153.04s41.14s
Low93.38s15.25s
High198.14s22.72s

We reran every ComfyUI case on the 5090 this way, and the CPU limit didn’t pause it once. If you benchmark in a container, check that the CPU count it reports matches the CPU time it’s allowed.

What’s next

We haven’t profiled the RTX 3090 High cases yet, and that’s where we look next. For Ideogram 4 on the H100, we’re looking at implementing a fast 256-wide head sage attention variant to beat the cuDNN kernel.

If your ComfyUI numbers for the same GPU differ a lot from ours, run the harness and tell us. That’s how this post started.
